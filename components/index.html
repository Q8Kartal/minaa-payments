Theming · 16

theme switch

A <jelly-switch> at the geometry of Figma 253:26, driving this page's <jelly-theme>. Checked is light: the drawing rests the thumb at the start for dark and at the end for light, and in an LTR page the start is the unchecked position. The icon sits in whichever half the thumb has left, and the two cross-fade rather than swap, because a swap at the end of the travel pops while the track colour is still crossfading.

Feedback · 17

toasts

The toasts from the Buttons page, unchanged and deliberately identical in both modes: a toast is a momentary overlay, and the four tones are semantic colours, which are never brand and therefore never mode-dependent. An error is Orange 500 whatever is behind it. Jelly gives every toast the same part="toast" with nothing to say which of the four it is, so the tone is read back off the dot and a second part name added; that is the only reason a per-tone colour is reachable from a stylesheet at all. Meaning never rests on the colour: each tone carries its own mark, and Jelly speaks a prefix for a screen reader.

Fires into the page’s one <jelly-toaster>, bottom centre. The buttons are page furniture rather than a specimen — <jelly-button> is not an entry in this library — so the snippet below shows the call, not them.

Overlays · 18

<jelly-dialog>

A modal panel. It is not a native <dialog> and never enters the top layer — it is fixed-position with its own backdrop — and on open it moves itself to document.body. The bridge still reaches it there, but a scoped <jelly-theme> does not: a dialog written inside one renders in the page’s mode, not the scope’s. The scrim is ours rather than Jelly’s, which derives it from the text colour and so washed the page cream in dark and red in light.

Overlays · 19

<jelly-drawer>

The dialog lying against an edge. Same portal, same scrim, same close control — and it inherited the same three bugs, so it takes the same three fixes rather than copies of them. side is not an observed attribute: it is read by CSS only, so setting it in JavaScript after load moves the sheet but fires no update. The corner is capped, not left to fill the space: a sheet is tall, and “as round as it can be” would stand a capsule on end. The cap is one value the whole overlay family shares, so a bottom sheet and a dialog of the same height draw the same corner — it tracks what the surface is, not how big it happens to be.

<jelly-popover>

A panel tethered to its trigger. Two named slots, and both are required: trigger is what you click, content is what appears. Unlike the dialog it does not portal and has no scrim, so it stays inside a scoped <jelly-theme> — the one overlay on this page that does.

Overlays · 21

<jelly-tooltip>

A hint on hover and on focus. The text is an attribute, not a slot, so it cannot carry markup — and it is the one component that names its own --jelly-tooltip-background and --jelly-tooltip-color instead of reading the surface tokens. Left alone it paints a near-black chip, which is a colour this system does not have.
